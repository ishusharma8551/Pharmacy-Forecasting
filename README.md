# Pharmacy Medicine Demand & Expiry Risk Forecasting

An end-to-end AI/ML inventory decision-support system for pharmacies: it forecasts medicine demand, estimates which
batches may expire unsold, and recommends reorders, overstock actions and first-expiry-first-out (FEFO) dispensing.

Internship project for **ALGIONS AI LABS PRIVATE LIMITED**.

> **Data notice:** all data in this repository is **SYNTHETIC**, generated by `data/generate_data.py`. Medicine names are generic names
> used for realism, manufacturers are fictional, and every quantity, price and sale is random. No patient or real pharmacy data is used.
> Model scores below demonstrate that the pipeline works; they are **not** evidence of real-world accuracy.
>
> Expiry-risk outputs are **inventory decision-support estimates**, not medical or regulatory determinations.

## Problem statement
Pharmacies lose money in two opposite ways: **stockouts** (lost sales, unserved patients) and **expiry write-offs** (capital sitting on shelves).
Both stem from poor demand estimates. This project predicts demand, converts it into expected unsold stock per batch, and turns that into actions.

## Objectives
1. Forecast demand for the next 7, 15 and 30 days.
2. Classify batches as Low / Medium / High expiry risk.
3. Compute reorder point, safety stock, order quantity, overstock and potential expiry loss.
4. Recommend FEFO dispensing order.
5. Provide a 6-page Streamlit dashboard backed by SQLite.

## Dataset
Three related tables (a flat CSV with all requested columns is also exported to `data/raw/pharmacy_inventory_flat.csv`):

| Table | Grain | Size |
|---|---|---|
| `medicines` | one row per medicine (name, category, prices, stock limits, lead time, seasonality) | 60 |
| `batches` | one row per batch in stock (purchase / manufacturing / expiry date, quantities) | ~180 |
| `sales_daily` | one row per medicine per day, 2 years | 43,800 |

Realism built in: 10 categories, weekday effects, seasonal patterns (winter / summer / monsoon), trend, overdispersed random
noise, occasional promotional spikes, different shelf lives, and a few already-expired batches. The **raw** sales file deliberately
contains faults (40 duplicates, 60 missing values, 15 injected outliers) that the cleaning step finds and fixes.
Real public pharmacy-inventory data is not available, which is why synthetic data is used.

## Methodology

**Demand forecasting.** Direct multi-horizon: a row is (medicine, forecast-origin day *t*). Features use only data up to *t*
(day-of-week, week, month, season, weekend flag, lags 0/1/6/13/27, rolling mean/std, medicine/category/seasonality codes). The target is
total units sold in days *t+1..t+h*. Split is **chronological**: last 90 days = test; the 60 days before = validation; training
targets must end before the next period starts (purged split). Models: 3 baselines (naive, 7-day and 28-day moving average),
Linear Regression, Random Forest, XGBoost. The ML model is **selected on validation error**, then scored on test. MAPE ignores zero actuals; WAPE is reported alongside.

**Expiry risk.** Historical inventory *snapshots* (2,400) are built; features are known at the snapshot date (days to expiry, stock,
trailing sales, an out-of-time forecast, turnover, batch quantity, category, expected unsold ratio). The **label comes from what actually
happened** (share unsold at expiry): Low < 15%, Medium 15-50%, High >= 50%. Expected Unsold Stock = Current Stock - Expected Units Sold before expiry.
Logistic Regression, Decision Tree and Random Forest are compared; selection prioritises **recall on High risk**. A rule baseline is reported to show whether ML adds anything.
For current batches, demand is allocated first-expiry-first-out.

**Inventory optimization.** Lead-time demand = forecast/day x lead time; safety stock = 1.65 x sigma x sqrt(lead time); reorder point = both added;
target = forecast x (lead time + 30 days) + safety stock, capped at maximum stock; order quantity = max(target - usable stock, 0) when stock <= reorder point.
All assumptions are listed in `config.py` and on the dashboard.

## Results (reference run on synthetic data; seed 42)
Full tables are regenerated in `reports/results_summary.md`. Numbers may differ slightly with library versions.

| Horizon | Best ML on **test** (MAE) | Moving Avg 28d baseline (MAE) | ML chosen on **validation** | its test MAE |
|---|---|---|---|---|
| 7 days | XGBoost 15.85 | 16.16 | Linear Regression | 16.28 |
| 15 days | XGBoost 26.81 | 28.73 | Linear Regression | 28.82 |
| 30 days | XGBoost 47.26 | 60.45 | Linear Regression | 61.18 |

Honest reading: ML gains over the 28-day moving average are **small at 7 days and larger at 30 days (XGBoost)**. Validation picked Linear Regression,
which on the test set is about equal to the baseline - validation windows are short and noisy, which is a real limitation of model selection.

Expiry-risk classifier, test set (601 snapshots; Low 235 / Medium 157 / High 209):

| Model | Accuracy | Macro-F1 | Recall (High) |
|---|---|---|---|
| Rule baseline | 0.857 | 0.847 | 0.914 |
| Logistic Regression (selected) | 0.854 | 0.840 | 0.900 |
| Decision Tree | 0.819 | 0.807 | 0.833 |
| Random Forest | 0.840 | 0.832 | 0.837 |

The simple rule is as good as the ML models here. This is expected on synthetic data where stock was generated from the same demand, and is
reported rather than hidden: on real data the learned model may or may not add value.

## Limitations and future work
Synthetic data only; one supplier and fixed lead time; no price/promotion/weather features; demand extrapolated linearly beyond 30 days for long-dated batches;
sigma estimated from history not forecast error; no multi-store transfers. Next steps: real data connector, prediction intervals (quantile regression),
hyper-parameter tuning with time-series cross-validation, store-level models, automated retraining, alerts by email.
